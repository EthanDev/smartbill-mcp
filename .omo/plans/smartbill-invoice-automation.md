# smartbill-invoice-automation - Work Plan

## TL;DR (For humans)

**What you'll get:** A Hermes-powered accounting assistant on your Mac Mini that you message over Telegram or WhatsApp. The whole thing is conversational: say `create` and it walks you through an invoice in short steps; send a photo/PDF of an invoice and it reads it and drafts the matching invoice; one-word verbs do everything else — `pdf`, `send`, `pay`, `storno`, `status`, `totals`, `ask`. You never open the SmartBill website. Nothing committal goes out without your explicit yes in chat.

**Why this approach:** The convenience is the product — quick verbs, upload-and-draft, reply-to-act, and smart defaults (series/VAT/currency/date) — while every committal step still needs your chat-level yes AND a machine-checkable confirm flag, so being fast never means being unsafe. Credentials live encrypted in Cloudflare, not on the Mini.

**What it will NOT do:** No SMS/WhatsApp invoice sending (SmartBill is email-only), no webhooks, no sync of invoices made in the SmartBill website, no sending without your approval, no changes to your existing expense pipeline.

**Effort:** Large
**Risk:** Medium - live SmartBill production tests (no sandbox exists); a token was shared in chat so a rotate-after-deploy step is included
**Decisions to sanity-check:** GitHub OAuth is the MCP's identity layer (invite-only via allowlist); single company seed (VOICEVUI SRL); CIF format `RO47247261` verified live during smoke, fallback `47247261`.

Your next move: hand this file to the Mac Mini Hermes instance and run it. Human steps it cannot do are marked HUMAN — you'll need: `wrangler login` (browser), **two** GitHub OAuth Apps (localhost + prod), Telegram BotFather token, WhatsApp Meta panel steps.

- Approval gate: committal actions require (a) unambiguous chat "yes" from the paired user after an echo of client/series/number/amount/recipient, AND (b) `confirm:true` passed to the MCP tool. Anything else ("yeah", emoji, silence) is NOT a yes.
- **Chat-first conversational UX (the convenience layer)**: the entire workflow is designed so the operator NEVER opens the SmartBill web app — everything is a short chat message. Design rules baked into the skill (Todo 10):
  1. **Quick verbs** — one word is enough: `create`, `send`, `pdf`, `pay`, `cancel`, `storno`, `status`, `ask`, `totals`, `list`, `upload`. Example: message `pdf 123` → PDF back; `pay INV123 1500` + yes → payment recorded.
  2. **Upload = auto-draft** — send an invoice PDF/photo to the chat → Hermes vision-parses it (client, products, totals, VAT, dates) → drafts a matching SmartBill invoice → asks "create it?" → yes → finalize/send. No typing of line items, ever.
  3. **Guided wizard** — for create-from-scratch: `create invoice` alone starts a fill-in-the-gaps wizard (client → what for → price → confirm), and each missing field is asked in ONE chat turn with smart defaults pre-suggested (series, 21% VAT, RON, today).
  4. **Reply-chain context** — replying to one of the agent's own messages acts ON that invoice: reply "send it" to the issued-invoice message → gate → sends; reply "storno" → gate → reverses. No invoice numbers needed.
  5. **Smart defaults + autocomplete** — client/product auto-suggest via `list_clients`/`list_products` fuzzy name match (type 3 letters); if a client name is ambiguous, agent offers the top 3 as tap-able choices; series defaults to the first `factura` series; `issueDate` = today (Bucharest); currency RON; VAT 21%.
  6. **Confirmation card** — every gate uses ONE compact message: client / series / number / amount / recipient + "reply yes to confirm or no". Nothing else.
  7. **Native tappable replies where the platform allows** — Telegram inline buttons (`rich_messages` config) / WhatsApp quick-reply if the gateway supports; otherwise text verbs. Never required — text always works.
